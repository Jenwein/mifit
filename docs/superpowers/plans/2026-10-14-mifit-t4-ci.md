# mifit T4 CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the offline test suite on GitHub Actions (Linux, every supported Python) on each push and pull request, and make the two DST tests run on the Windows dev machine too.

**Architecture:** A `test` extra in `pyproject.toml` (`pytest`, `tzdata`) is the one install command for both CI and local runs: `pip install -e ".[test]"`. `tzdata` gives Windows the IANA zone database that `zoneinfo` lacks there, so the two DST tests stop skipping. An autouse fixture in `tests/conftest.py` refuses every socket connection, so "the tests are offline" is enforced rather than assumed. One workflow, `.github/workflows/ci.yml`, runs `pytest` on `ubuntu-latest` for Python 3.12, 3.13 and 3.14 with no secrets and a read-only token.

**Tech Stack:** GitHub Actions (`actions/checkout@v7`, `actions/setup-python@v7`), pytest, `tzdata` (PyPI, test extra only). No new runtime dependency.

**Spec:** roadmap `docs/superpowers/roadmap.md` §4 T4 ("GitHub Actions 在 Linux 上跑 `pytest`（Linux 有 tzdata，夏令时用例会真正执行）") and §2 row "夏令时用例在本机因缺 tzdata 被跳过"; design `docs/superpowers/specs/2026-10-13-mifitness-sdk-design.md` §3 (Python 3.12+, few dependencies, low-frequency access: CI must never call the Xiaomi cloud).

## Review Focus

- **A test that silently skips on CI** (e.g. the zone database missing): the suite must report it. → Task 2 runs `pytest -q -rs` (skip reasons in the log) and Step 7 checks the log says `0 skipped`/no `SKIPPED` line.
- **A future test that forgets the fake transport and reaches the network** (from GitHub's IPs, against Xiaomi): it must fail, not pass quietly. → Task 1 `test_tests_cannot_reach_the_network` + autouse guard.
- **The runner's machine zone is UTC**: a test meant to cover another zone that relies on the machine default would pass vacuously on CI. All current zone tests pass `tz` explicitly (checked: 275/275 on Linux); no new test needed, but the reviewer checks any new zone test passes `tz`.
- **Floor vs newest Python drift** (a 3.13+-only construct in `src/`, or a 3.14 deprecation): the matrix runs 3.12 and 3.14. → Task 2 matrix.
- **POSIX-only assertions** (`test_session_store` `0o600`) run for the first time on Linux: they passed at plan time. → covered by the first CI run (Task 2 Step 6).

### Task 1: `test` extra with tzdata, and an offline guard

**Files:**
- Modify: `pyproject.toml` (new `[project.optional-dependencies]` table, before `[project.scripts]`)
- Modify: `tests/conftest.py` (append the guard fixture)
- Create: `tests/test_offline.py`

**Interfaces:**
- Produces: `pip install -e ".[test]"` installs `pytest>=8` and `tzdata`; every test runs with `socket.getaddrinfo`, `socket.create_connection`, `socket.socket.connect` and `socket.socket.connect_ex` replaced by a function raising `RuntimeError("tests must not use the network")`. Task 2's workflow uses the extra.

- [ ] **Step 1: Write the failing test** `tests/test_offline.py`:

```python
"""The suite is offline: any attempt to reach the network fails the test."""

import socket

import pytest
import requests


def test_tests_cannot_reach_the_network():
    # Numeric address (TEST-NET-1): resolving it needs no DNS, so even the
    # unguarded red run sends nothing.
    with pytest.raises(RuntimeError, match="network"):
        socket.getaddrinfo("192.0.2.1", 443)
    with pytest.raises(RuntimeError, match="network"):
        socket.create_connection(("192.0.2.1", 443), timeout=1)
    with socket.socket() as sock:
        sock.settimeout(1)
        with pytest.raises(RuntimeError, match="network"):
            sock.connect(("192.0.2.1", 443))
    with pytest.raises(RuntimeError, match="network"):
        requests.get("https://192.0.2.1/", timeout=1)
```

- [ ] **Step 2: Run** `python -m pytest tests/test_offline.py -v` → FAIL with `DID NOT RAISE <class 'RuntimeError'>` at the first `getaddrinfo` block.

- [ ] **Step 3: Implement** in `tests/conftest.py` an autouse fixture `_no_network(monkeypatch)` that `monkeypatch.setattr`s the four names above to one module-level `_refuse(*args, **kwargs)` raising `RuntimeError("tests must not use the network")`. `RuntimeError`, not an `OSError` subclass: `urllib3`/`requests` and the CLI would turn an `OSError` into an ordinary "network error" and hide the guard. Extend the module docstring by one sentence saying so. In `pyproject.toml` add:

```toml
[project.optional-dependencies]
# For running the tests: pytest, and the IANA zone database for the DST tests on
# systems that have none (Windows).
test = ["pytest>=8", "tzdata"]
```

- [ ] **Step 4: Run** `python -m pip install -e ".[test]"` then `python -m pytest -q -rs` → `276 passed`, no `skipped` (the two DST tests now run on Windows).

- [ ] **Step 5: Commit**

```bash
git add pyproject.toml tests/conftest.py tests/test_offline.py
git commit -m "test: tzdata test extra so DST tests run on Windows; refuse network in tests"
```

## Decisions

1. **Matrix 3.12 / 3.13 / 3.14 on `ubuntu-latest` only.** 3.12 is `requires-python`'s floor, 3.14 is the dev machine's Python (3.14.7), 3.13 sits between; the suite takes about a second, so three jobs cost nothing. Newer Pythons are added when they are released and in use. No Windows job: the roadmap asks for Linux, and Windows is the dev machine, where the suite now runs in full.
2. **`tzdata` as a `test` extra, not a runtime dependency and not "leave it".** Leaving it keeps the §2 gap (the DST tests never run where development happens). A runtime dependency is unneeded: `src/` never builds a `ZoneInfo` and defaults to the machine zone; a caller who passes `tz=ZoneInfo(...)` on Windows installs `tzdata` as Python's docs advise. An extra over a PEP 735 dependency group: `pip install -e ".[test]"` works with every pip in the matrix.
3. **`pytest>=8`**, no upper bound; `tzdata` unpinned (the DST rules tested date from 2007).
4. **Enforce offline with a socket guard** (autouse fixture raising `RuntimeError`) rather than trust convention: CI from GitHub's IPs must never reach Xiaomi (design §3 low-frequency, account-risk constraint). The trial run showed nothing legitimate needs a socket.
5. **Triggers `push` (all branches), `pull_request`, `workflow_dispatch`**; `permissions: contents: read`; no secrets; `timeout-minutes: 10`; `fail-fast: false` so one Python's failure does not hide another's. No pip cache (install is seconds).
6. **Actions by major tag** (`@v7`, released 2026-07-20) rather than commit SHA: the token is read-only and the job holds no secrets. No Dependabot config (YAGNI).
7. **`pytest -q -rs`** in CI so any skip prints its reason.
8. **README gets a badge and a short "Development" section** (README exists on `main` after T1).
9. **Roadmap §1's test-count line is not touched** (the task limits edits to §0/§2/§4); the next milestone update refreshes it.
