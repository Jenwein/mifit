# mifit 0.3.2 (phase E minors) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship mifit 0.3.2 with the minor findings deferred from phase E's final review fixed: the GPS hints reach Claude Desktop extension users, and the release workflow checks a little more before it publishes.

**Architecture:**
- **One library change, texts only.** The GPS refusal and the GPS parts of the tool descriptions name the extension's "Allow GPS tracks" switch next to `--allow-gps`. No behavior changes.
- **Release plumbing:**
  - `tools/release.py`:
    - `check-version` gets `--owner`; on tags, CI passes `$GITHUB_REPOSITORY_OWNER`.
    - `check-mcpb` compares each bundle member's bytes with `packaging/mcpb/`.
  - `tools/mcp_handshake.py` gets `--expect-version` and checks `serverInfo.version` against it.
  - `.github/workflows/release.yml`:
    - the build job uploads `server.json` first;
    - the step name and the help text say what `check-version` checks;
    - the mcpb job passes the version it builds;
    - the registry retry loop does not sleep after its last try.
- **Packing hygiene and docs:**
  - `packaging/mcpb/.mcpbignore` is new;
  - `.gitignore` ignores `packaging/mcpb/uv.lock`;
  - the README says the extension pins its release;
  - version 0.3.2 goes into the six places `check-version` covers, and the CHANGELOG gets a 0.3.2 section.

**Tech Stack:** Python 3.12+ (stdlib only in `tools/`), pytest + PyYAML (the existing `test` extra), GitHub Actions bash, `@anthropic-ai/mcpb` 2.1.2 (for the local pack check only).

**Spec:** the "Final: minor (deferred)" lines of the phase E ledger. A copy is in the shared session notes: `e-ledger.md`, in the folder `side-session-notes/local_6bac3be0-…`. ## Facts checked on 2026-10-16

- **Tool and server versions.**
  - `mcpb pack` 2.1.2 (`dist/node/files.js`) always leaves out `.mcpbignore` itself, `.gitignore`, `.git`, `*.log`, `.env*`, `*.mcpb` and a few Node files.
  - The extra patterns in `.mcpbignore` follow gitignore syntax (the `ignore` package), one per line; `#` starts a comment.
  - The packer checks a directory by its relative path without a trailing slash. So write the patterns without one: `.venv` skips the whole directory.
  - The server already reports `serverInfo.version = mifit.__version__` (`MCPServer(SERVER_NAME, version=mifit.__version__, ...)`, `server.py:476`).
- **What the 0.3.1 run showed.**
  - The packed 0.3.1 bundle's members were byte-equal to `packaging/mcpb/`: `pack` copies the bytes as they are.
- **The runners.**
  - CI (`ci.yml`) runs pytest on ubuntu-latest only.
  - The workflow runs `run:` blocks with `bash --noprofile --norc -eo pipefail {0}` (`defaults.run.shell: bash`).

## Global Constraints

- Files are LF. Python's `write_text` on this machine writes CRLF: normalize after scripted edits.
- `tools/` stays standard library only.
- The README marker stays exactly `<!-- mcp-name: io.github.Jenwein/mifit -->`.

- Version `0.3.2` goes in:
  - `pyproject.toml`;
  - `CHANGELOG.md` (`## 0.3.2 — 2026-10-16`);
  - both versions in `server.json`;
  - `packaging/mcpb/manifest.json`;
  - `packaging/mcpb/pyproject.toml`: its version, and the pin `mifit==0.3.2`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Nothing is pushed or tagged without the user's own go-ahead. A tag publishes to PyPI and the MCP Registry at once, and it cannot be undone.

## Decisions

- **M-D1: `--allow-gps` stays in every text, and the switch is added.**
  - Users of `uvx mifit mcp` still need the flag.
  - The tests already pin `--allow-gps`, so they keep passing; the new test pins the switch as well.
- **M-D2: `--owner` is optional; CI always passes it on tags.**
  - Local runs (`check-version --tag vX.Y.Z`) keep working without it.
  - The check is a case-sensitive prefix test, like the registry's own.
  - An empty owner fails the check. That happens when `$GITHUB_REPOSITORY_OWNER` is unset.
- **M-D3: `bundle_problems` takes the sources directory as an argument** (`sources: Path`); `main` passes `ROOT / BUNDLE_DIR`.
  - The manifest version check stays, because it gives the clearer message.
- **M-D4: `handshake()` returns `(server_info, tool_names)`.**
  - `--expect-version V` must come first: `mcp_handshake.py [--expect-version V] COMMAND [ARG...]`.
  - Everything after it is the command, verbatim, as before.
- **M-D5: the registry loop keeps its 6 tries, 20 s apart**, and does not sleep after the 6th.
  - Its other rough edges stay as they are, and stay listed: a permanent error is retried, and a lost success reply turns the later tries into "already exists". Fixing those needs a registry lookup, which is out of scope.

## Review Focus

1. **`--owner ""`.** `$GITHUB_REPOSITORY_OWNER` is unset outside GitHub. Expected: a problem is reported, not a pass. Test: Task 2.
2. **The owner's case differs** (`jenwein` against `io.github.Jenwein/mifit`). Expected: a problem is reported. Test: Task 2.
3. **A server whose `initialize` reply has no `serverInfo`,** run with `--expect-version`. Expected: `error:` and exit 1, not a `KeyError` traceback. Test: Task 3.
4. **`--expect-version` with no value, or with no command after it.** Expected: `error:` and exit 1, not an `IndexError`. Test: Task 3.
5. **The publish succeeds on the 6th try.** Expected: exit 0 after 5 sleeps. When all 6 tries fail: exit 1 after 5 sleeps, not 6. Test: Task 4.
